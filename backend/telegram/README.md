# VakDab Telegram Bot + Site Worker

Один Cloudflare Worker обслуговує сайт VakDab і Telegram-бота:

```text
/                    → статичний сайт VakDab
/telegram-webhook    → Telegram webhook бота
/set_webhook         → захищене встановлення webhook
```

Worker має залишатися на адресі `https://vakdab.vakdabpro.workers.dev/`, якщо саме цей домен налаштований у правильному Cloudflare-акаунті.

## Важливо для Cloudflare Build

GitHub repository: `vakdab/Vakdab`. Root directory залиште порожнім, щоб у deployment були доступні і сайт у корені репозиторію, і `backend/telegram/worker.js`.

Deploy command потрібно виконувати з каталогу Worker:

```bash
cd backend/telegram
npx wrangler deploy
```

`wrangler.toml` містить assets binding, Durable Object binding `CHAT_ROULETTE` і SQLite migration для `ChatRouletteRoom`. Перший deploy із цією migration створює storage для черги та активних сесій. **Публікація коду в GitHub не є deploy-ом Cloudflare Worker.** Перед запуском команди перевірте, що Wrangler авторизований саме в Cloudflare-акаунті, де існує Worker `vakdab` і домен `vakdab.vakdabpro.workers.dev`.

## Telegram-функції

Кнопка **«Випадкове»** спочатку пропонує **Аніме / Манґа / Ранобе**, після чого бот вибирає випадковий запис відповідного типу. Кнопка **«Пошук»** працює аналогічно: спочатку обирається тип, потім користувач вводить назву. Усі три типи використовують allowlisted endpoint-и Hikka `/anime`, `/manga` і `/novel`; для манґи та ранобе бот не показує фальшиве посилання на anime player.

Популярні аніме та розклад залишаються окремими anime-only flows. Для аніме доступна кнопка **«Дивитись на VakDab»**, а для манґи й ранобе бот показує деталі та постер із посиланням на Hikka, якщо Telegram не може відкрити внутрішні деталі. Кнопка **«Розклад»** відкриває `app/schedule.html` як Telegram Mini App: сайт відображає наданий банер, актуальні дані API та читабельні вкладки від понеділка до неділі. Технічна назва джерела даних користувачу не показується.

### Обов’язкова підписка на канал

Після команди `/start` бот перевіряє підписку користувача на канал [`@vakluna`](https://t.me/vakluna) через Telegram Bot API. Якщо підписка підтверджена, бот показує головне меню; якщо ні — надсилає повідомлення без видимого тексту, лише з двома кнопками: **«Підписатися на канал»** і **«Підписався(лась)»**. Для роботи `getChatMember` VakDabBot потрібно додати до каналу адміністратором із правом бачити учасників.

### Луна

Основна кнопка AI тепер називається **«Запитати Луну»**. Підтримуються команди `/luna <запит>` і `/ask <запит>`. Луна підтримує розмови на широке коло тем, зокрема стосунки, флірт, секс і тіло між повнолітніми — без автоматичного моралізаторства. Тему війни, бойових дій та політичного насильства вона не обговорює. Тимчасові помилки або rate limit AI-провайдера повторюються автоматично; якщо сервіс усе ж недоступний, бот відповідає дружнім повідомленням і просить повторити репліку, а не показує технічну помилку. Команда `/luna` активує режим Луни й без аргументів залишає його активним для наступних повідомлень. Команда `/clear` мовчки видаляє з Telegram усі доступні tracked-повідомлення користувача та Луни, включно із самою командою, але не стирає `history`, `summary` або `profile`, тому Луна зберігає контекст і пам’ять. Для кожного нового повідомлення використовується окремий KV-індекс, щоб очищення не обмежувалося останніми 160 записами. Команда `/makima` та `/ask` тимчасово залишаються backward-compatible alias для старих користувачів. Команда `/memory` показує збережені про користувача факти без AI-запиту, `/forget` очищує історію діалогу, а `/forgetall` — історію та профіль. Memory binding збережено під старою технічною назвою `MAKIMA_MEMORY`, тому існуюче сховище пам’яті не втрачається під час перейменування на Луну.

### Анонімна Чат-Рулетка

Після натискання **«Чат-Рулетка»** користувач спочатку бачить правила, а потім може натиснути **«Знайти співрозмовника»**. Pairing виконується всередині одного Durable Object, тому queue/session changes серіалізуються й не залежать від локальної пам’яті процесу Worker. Активна сесія підтримує текст, стікери, GIF/animation, фото, відео, video note, audio, voice та document. Для медіа Worker використовує відповідний Telegram Bot API `send*` метод із server-side `file_id`, тому одержувач не бачить username або профіль відправника; звичайний текст і невідомі сумісні типи передаються через `copyMessage`.

Під час розмови бот не додає кнопки під пересланими повідомленнями. Команда **`/next`** завершує поточний діалог і відразу починає пошук нового співрозмовника. Команда **`/report`** спочатку показує вибір причини: образи або цькування, спам або реклама, погрози або небезпека, небажаний інтимний контент чи інша причина. Після вибору причина зберігається разом зі скаргою, а сесія завершується. Після 18 скарг на користувача його доступ до чат-рулетки блокується на 3 дні. Список користувачів, скарги та блокування зберігаються постійно; старі звіти не видаляються. Є захист від повторних webhook updates, базовий rate limit і блокування посилань/контактів/доксингу. Це **не повна автоматична модерація**: користувачам не слід надсилати персональні дані чи погоджуватися на небезпечні пропозиції.

### Приватна статистика

Worker зберігає постійний список користувачів, які взаємодіяли з ботом: Telegram user ID, username, відображуване ім’я, дату першої та останньої активності й кількість взаємодій. Команда **`/F8`** доступна лише власнику з username `@vaditx`; вона показує користувачів, окремий список людей зі скаргами, причини скарг і активні 3-денні блокування. Дані користувачів і скарг не видаляються автоматично.

## Джерела даних VakDab

- **Hikka API** (`https://api.hikka.io`) — Telegram-пошук, випадковий контент, популярні аніме, назви, постери, жанри, статус, рік, описи й кількість епізодів/розділів.
- **Mikai API** (`https://api.mikai.me/v1/schedule`) — розклад виходу.
- **VakDab** (`https://vakdab.github.io/VakDab`) — anime deeplink через `#anime/{hikka-slug}`.
- **Proxy** (`https://monoanime.animegran8.workers.dev`) — залишається доступним для сумісності з іншими запитами Worker.

## Cloudflare secrets

У Worker потрібно додати secrets:

```text
TELEGRAM_BOT_TOKEN
WEBHOOK_SETUP_SECRET
TELEGRAM_WEBHOOK_SECRET_TOKEN  # рекомендовано для перевірки X-Telegram-Bot-Api-Secret-Token
BAZAARLINK_API_KEY              # для AI-режиму Луни
```

Для AI-асистентки додайте secret `BAZAARLINK_API_KEY`. Worker використовує OpenAI-сумісний endpoint `https://api.bazaarlink.ai/v1` і модель `auto:free` за замовчуванням; її можна змінити через змінну `BAZAARLINK_MODEL`, наприклад на `openai/gpt-4o`. `auto:free` не є безлімітним: безкоштовні моделі можуть мати обмеження швидкості та доступності. За потреби endpoint можна перевизначити змінною `BAZAARLINK_BASE_URL`.

`GROQ_API_KEY` і `GROQ_MODEL` залишаються резервним fallback для сумісності: якщо `BAZAARLINK_API_KEY` заданий, він має пріоритет. Якщо memory storage використовується у production, binding KV має залишатися доступним як `MAKIMA_MEMORY`, щоб не втратити стару історію після перейменування на Луну.

Секрети не зберігаються в GitHub і не записуються в код. Додайте ключ до Worker командою `npx wrangler secret put BAZAARLINK_API_KEY` з каталогу `backend/telegram`; вставляйте повне значення лише в інтерактивний prompt Wrangler. Не додавайте його до `.env`, комітів, issue або повідомлень чату.

## Встановлення Telegram webhook

Webhook має вести не на корінь сайту, а на Telegram-маршрут:

```text
https://vakdab.vakdabpro.workers.dev/set_webhook?url=https%3A%2F%2Fvakdab.vakdabpro.workers.dev%2Ftelegram-webhook&secret=<WEBHOOK_SETUP_SECRET>
```

Перевірити стан можна через Telegram Bot API:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo
```

Після цього сайт відкривається як раніше, а Telegram надсилає updates на `/telegram-webhook`.

```bash
node --test tests/telegram/telegram-worker.test.mjs
node --input-type=module --check < backend/telegram/worker.js
```

Локальний syntax/test pass або push у GitHub підтверджує лише код у репозиторії. Він не підтверджує, що production Worker уже задеплоєний або що webhook переключено.
